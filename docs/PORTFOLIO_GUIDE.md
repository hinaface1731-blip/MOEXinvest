# Личный портфель

Портфель работает в серверной версии `/moex`, не в публичной демонстрации GitHub Pages.
Он хранится в существующей SQLite-базе Daily Stock Analysis. Реальных сделок приложение не совершает.

1. Создайте рублёвый счёт в разделе «Мой портфель».
2. Запишите фактические пополнения и выводы. Это внешние денежные потоки, а не прибыль.
3. Внесите покупки и продажи: дату, количество отдельных бумаг (не лотов), цену и комиссию.
4. Для облигаций укажите **полную цену одной бумаги в рублях с НКД** и выберите соответствующий
   тип цены. Биржевая цена в процентах от номинала не подходит для этого поля. Возьмите
   фактическую сумму расчётов из брокерского отчёта, а не текущий НКД для исторической сделки.
5. Укажите уникальный номер сделки из отчёта. Повторный импорт этого номера не создаёт дубликат.
6. Купоны/дивиденды внесите после реального получения. Поле выплаты задаётся на одну бумагу
   и применяется к количеству в журнале на выбранную дату. Если количество на дату фиксации
   прав отличается от количества на дату поступления, сначала согласуйте события журнала;
   автоматический расчёт entitlement/налогов для таких случаев не реализован.

Комиссия учитывается в себестоимости и денежных остатках. Продажа сверх учтённого количества
отклоняется. Погашение облигации можно внести как продажу погашенного количества по фактической
сумме расчётов; автоматическое начисление амортизаций не выполняется.

## CSV

Вставьте CSV с заголовком (UTF-8, разделитель — запятая):

```csv
symbol,trade_date,side,quantity,price,fee,price_basis,trade_uid
SBER,2026-11-16,buy,10,295.50,1.00,rub,example-stock-001
SU26248RMFS3,2026-11-16,buy,1,820.00,0.50,dirty_rub,example-bond-001
```

**Значения выше — пример формата, не биржевые цены.** Замените их реальными операциями.
`side`: buy/sell; `price_basis`: rub для акций/фондов, dirty_rub для облигаций.
В одном импорте не больше 1000 строк. Каждая строка сохраняется отдельной транзакцией;
ответ содержит её статус. После ошибки исправьте строки и повторите с исходными trade_uid.
Удалять или исправлять ошибочные события можно через существующий Portfolio API исходного проекта.

## Оценка и доходность

- Текущая стоимость облигации: количество × (процентная цена × номинал / 100 + НКД).
- Устаревшие или отсутствующие котировки не подменяются нулевой стоимостью всего портфеля:
  полная оценка помечается недоступной, известная часть сохраняется отдельно.
- Прибыль = стоимость портфеля − чистые внешние пополнения. Корректность требует полной истории.
- XIRR: годовая денежно-взвешенная доходность ACT/365F с датами пополнений/выводов.
  При недостаточных данных или неоднозначных потоках отображается прочерк.
- Просадка рассчитывается по сохранённым полным оценкам после последнего внешнего потока.
  Она не объявляется полной исторической просадкой до появления соответствующей истории.
- Доли эмитентов считаются по известной стоимости ценных бумаг, без денежных остатков.
- Купонный календарь информационный: прогнозные выплаты не увеличивают остаток автоматически.

Серверное приложение имеет один общий личный портфель. Добавляйте в Telegram allowlist только
тех, кому разрешён доступ ко всем его счетам. Для разделения пользователей нужны отдельные базы/инстансы.
