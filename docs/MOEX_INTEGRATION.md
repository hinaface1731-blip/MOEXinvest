# Аудит и план интеграции MOEX

## Исходная точка

Аудит выполнен 17 ноября 2026 года для Daily Stock Analysis,
commit `aa7228986f0ac8fc78e9147be81dddb277ef342d` (версия changelog 3.35.0).
Исходники получены из `https://github.com/ZhuLinsen/daily_stock_analysis`.
Рабочая копия находится в MOEXinvest; origin остаётся репозиторием пользователя.
Лицензия и уведомления исходного проекта сохранены. Публикация не выполнялась.

**Статус: реализованы провайдер MOEX, российские API и React-раздел `/moex`,
облигационные расчёты, рублёвый портфель, CBR-макро, отчёты, Telegram polling и Pages-сборка.**

Аудит ниже фиксирует исходную точку. Реализация находится в `data_provider/moex_provider.py`,
`src/services/moex_analytics.py`, `moex_service.py`, `russian_macro.py`,
`api/v1/endpoints/moex.py` и `apps/dsa-web/src/pages/MoexPage.tsx`.
Существующий журнал портфеля расширен рынком ru и купонами; торговые цены облигаций
в журнале — полная стоимость одной бумаги в RUB. Стандартный equity pipeline отклоняет облигации.

LLM использует существующий `GeminiAnalyzer.generate_text`, но ответ ограничен выбором
идентификаторов уже проверенных фактов и рисков. Свободный текст не принимается как
источник чисел. Это ограниченный режим фактологического обзора, а не произвольный
диалоговый инвестиционный советник. Без ключа формируется прозрачный шаблонный обзор.

## Существенные ограничения текущего кода

- Поддерживаемые рынки портфеля: cn, hk, us, jp, kr, tw. Добавление одного fetcher не включает российский рынок во всех слоях.
- Буквенные тикеры могут восприниматься как иностранные акции. Предпочтительна явная форма `MOEX:SBER`; короткие имена допустимы внутри явно выбранного рынка ru после проверки справочника.
- В портфеле есть покупки, продажи, комиссии, денежный журнал, дивиденды, FIFO/средняя стоимость. Оценка позиции через количество × цену акции неприменима к процентной цене облигации.
- Купонная доходность, доходность к погашению и к оферте — разные показатели. Неизвестные будущие купоны исключают точный расчёт YTM.
- Календарь содержит fail-open поведение для некоторых проверок. Для MOEX необходимы явные состояния «неизвестно» и «устарело».
- Текущий workflow запускается в 10:00 UTC по будням. Будни не заменяют торговый календарь; Actions не гарантирует точное время и не является постоянным Telegram-процессом.
- Docker Compose использует Asia/Shanghai и публикует порт на всех интерфейсах. Для русского варианта нужны Europe/Moscow, локальная привязка и аутентификация перед внешним доступом.
- Единого Python lockfile нет: requirements.txt содержит диапазоны версий. Frontend имеет package-lock.json и устанавливается через npm ci.

## Последовательность реализации и критерии приёмки

1. **Основа:** установить зависимости, собрать WebUI, проверить API, выполнить существующие тесты портфеля, идентификации, календаря и индикаторов. Зафиксировать результаты отдельно от новых тестов MOEX.
2. **MOEX MVP:** получить реальные схемы ISS; сохранить обезличенные публичные fixtures с URL и датой получения. Реализовать HTTP-клиент с timeout, ограниченными повторами для 429/5xx, rate limiting, TTL-кешем и пагинацией. Разрешать SECID, ISIN, engine, market, board через справочник. Нормализовать даты, валюту, единицы цены, источник, fetched_at и timestamp биржи. Проверить SBER, YDEX, X5, IMOEX и отсутствие котировки. Подключить к существующим CLI/API/менеджеру источников без fallback российского инструмента на одноимённый иностранный.
3. **Акции:** использовать существующий движок, дополнить индикаторы; отдельно тестировать lookback, NaN, деление на ноль, split/dividend adjustment и benchmark alignment. Доходность с дивидендами показывать только при полной истории выплат.
4. **Облигации:** подтвердить SECID/ISIN ОФЗ 26248, 26243, 26247 по ISS. Хранить цену в процентах, номинал, НКД и график денежных потоков отдельно. Явно задавать settlement, day-count, амортизацию, даты оферт, календарь. Тесты PV/YTM, duration, modified duration и сценариев ставки; неизвестные потоки возвращают ограничение, а не выдуманное число.
5. **Макро и портфель:** проверить официальные машиночитаемые источники; сохранять observation_date, publication_date (nullable, если неизвестна), fetched_at и URL. Расширить существующие события портфеля, CSV и ручной ввод. Проверить, что пополнения не увеличивают прибыль; TWR/XIRR рассчитывать только при достаточных данных. Не подключать брокеров.
6. **ИИ:** структурированные факты и расчёты формирует Python. LLM интерпретирует факты с идентификаторами источников; числовые таблицы рендерятся из данных. Неизвестные числа/источники в ответе отклоняются. Отчёт: резюме, факты, техника, фундаментальные данные, макро, риски, три сценария, условия неактуальности, источники, время.
7. **Telegram и Web:** переиспользовать sender, dispatcher, API и React. Авторизация до чтения портфеля; тесты чужого user ID, пустого allowlist, групп и ошибок доставки. Русские страницы обзора, портфеля, акций, облигаций, макро, новостей, ИИ, истории и настроек; мобайл, темы, графики и состояния отсутствия данных.
8. **Эксплуатация:** отдельный ручной/плановый Actions workflow и Docker Compose; защищённое устойчивое хранение портфеля, идемпотентность отчётов, обработка недоступных источников. GitHub Secrets вводит пользователь. Команды Telegram требуют работающего процесса или webhook; ежедневные отчёты могут работать без VPS.
9. **Приёмка:** fixtures/unit-тесты отдельно от opt-in network-тестов; регрессия исходных рынков, сборка и UI smoke, инструкции README_RU, RUSSIAN_MARKET_SETUP, PORTFOLIO_GUIDE и актуальный .env.example. Полная готовность только после выполнения этих этапов.

## Состояние доступа к источникам

Первоначально запрос к `https://iss.moex.com/iss/securities/SBER.json` был заблокирован прокси (403).
После публикации среды доступ восстановлен; справочники, котировки и история проверены живыми запросами HTTP 200.
Подтверждены ISIN: 26248 — RU000A108EH4; 26243 — RU000A106E90; 26247 — RU000A108EF8. В черновике настроек подготовлены
`iss.moex.com`, `www.cbr.ru`, `cbr.ru`, `rosstat.gov.ru`, `minfin.gov.ru`.
Сохранение черновика само по себе не применяет сетевые изменения.
Публичные ответы для воспроизводимых тестов сохранены в tests/fixtures/moex вместе с источниками.
Нельзя выдавать синтетические fixtures за проверенные ответы биржи.

## Управление изменениями

Не заменять существующие провайдеры, UI framework или журнал портфеля.
Добавлять новые возможности по этапам и запускать соответствующие регрессионные тесты.
Не выполнять реальные сделки. Платные сервисы, публикация и внешняя инфраструктура требуют отдельного согласования.
Работать в существующей изолированной копии; git worktree не нужен.
Текущие добавления документации можно откатить отдельно от импортированной исходной базы.

## Проверенные ограничения реализации

- Официальный вызов `securities/SBER/dividends.json` в этой среде вернул справочник бумаги,
  а не таблицу dividends. Такой ответ не принимается за дивидендные данные: total return отсутствует,
  пользователь вводит фактически полученные дивиденды вручную.
- Полный график облигаций загружается по `coupons.start`, `amortizations.start`, `offers.start`;
  только при известных будущих суммах рассчитываются IRR ACT/365F и дюрация. Это не утверждение
  о совпадении с методикой биржевой доходности. Оферты, плавающие купоны и кредитные рейтинги
  показываются с ограничениями.
- Следующая торговая сессия не угадывается по буднему дню: показывается последняя наблюдённая
  сессия и наличие сегодняшних сделок. Будущий график при отсутствии проверенного источника — unknown.
- CBR HTML-таблицы ставки и инфляции, XML валют, RSS новостей и календарь заседаний проверены
  фактическими ответами. Дата публикации наблюдения nullable, дата получения не подменяет её.
- Pages — статический публичный снимок; личные функции требуют Python-сервера.
- API-ключи LLM/Telegram не заданы в среде. Транспорт Telegram проверен без реальной отправки;
  платные LLM-вызовы не выполнялись. Docker-образ собран, запуск приложения и защита API проверены.
- Исходные README на других языках не переписаны: русская интеграция документирована отдельно,
  основной интерфейс и инструкции иностранных рынков сохранены.
